Pareto-Optimal IQA for CLIP-Based Architectures

01

Problem

A more accurate IQA model is not automatically a better metric: the encoder may be too slow, too large, or too expensive for production. This project searches for non-dominated encoder/head pairs under one fixed training and evaluation protocol.

Research question How much OOD quality can be extracted from each selected encoder, and which model pairs remain on the Pareto frontier when latency, memory, and trainable parameters are included?

Core encoder shortlist

  • CLIP ViT-L/14 @ 336
  • SigLIP 2 So400m @ 384

Optional efficiency extension

FastViTHD from FastVLM. Add it only after the core pipeline is complete and it can return pooled and patch features through the same encoder API.

Scope: CLIP-based encoders are the core study. FastViTHD is an optional extension, not a replacement for the core comparison.

Query pooling

H2

Pareto axes: maximize macro OOD SRCC; minimize end-to-end batch-1 latency, peak inference VRAM, and trainable parameters. Use the same GPU, precision, and encoder-native input size for every measurement.

  4. Step 4

    Prove one path end to end

    • Normalize every score to [0, 1], higher means better.
    • Use content/reference-disjoint splits where reference IDs exist.
    • Overfit 64 images with CLIP + S0, then CLIP + H0.
    • Run one complete CLIP + H0 experiment before adding another head or encoder.
    • Never use an OOD test dataset for model selection.
  5. Step 5

    Build the Pareto matrix

    Run S0/H0/H1/H2 on CLIP first. Keep H0 and the two strongest heads for SigLIP 2. Measure quality and inference cost with one benchmark script. Add FastViTHD only if the core results are complete.

04

Expected result

The project is complete when the team can show which encoder/head pairs are non-dominated and recommend a model for at least two operating points: maximum quality and low latency.

01

Unified benchmark

One feature API, one trainer, one evaluator, fixed manifests, and reproducible configs for every completed encoder/head pair.

02

Results matrix

Three-seed OOD SRCC by dataset, macro SRCC, worst-dataset SRCC, parameters, latency p50/p95, and peak VRAM.

03

Pareto plot

Macro OOD SRCC versus batch-1 latency, with encoder, head, parameter count, and VRAM encoded in the exported table.

04

Deployable scorer

A minimal POST /score endpoint for the selected quality-first and speed-first configurations.

Primary decision rule

A model is Pareto-optimal if no tested model is both more accurate on macro OOD SRCC and cheaper on end-to-end latency. Report the full frontier; do not force a single winner.
