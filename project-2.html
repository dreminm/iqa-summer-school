Baseline и исследуемая гипотеза

WACV 2026 задаёт сильный baseline для pooled features. В проекте сравниваются головы, которые извлекают quality signal из pooled, patch- и intermediate-layer features полностью frozen CLIP-based энкодеров.

Модели

Отобранные энкодеры и расширение шортлиста

Core-протокол начинается с двух отобранных CLIP-based энкодеров. Дополнительные энкодеры подключаются после фиксации голов и правил сравнения.

IDCheckpointЗачемОграничение
E1openai/clip-vit-large-patch14-336Исходный shortlist; 24×24 patch grid + class token.Старая contrastive pretraining recipe; неизменный input 336.
E2google/siglip2-so400m-patch16-384Актуальный SigLIP 2; более плотные признаки при приемлемом 24 GB бюджете.Большой encoder; начинайте с batch 2 и gradient accumulation.
Расширение шортлистаПосле core-матрицы можно добавить FastViT-HD или другой encoder, прошедший screening. Для честного сравнения он должен работать через тот же feature API; данные, головы и budget остаются неизменными, а latency и VRAM измеряются end-to-end при его нативном input resolution.
Условия сопоставления с WACV 2026В статье используется google/siglip2-so400m-patch16-512 и LoRA. Основная матрица проекта использует frozen-384, поэтому результаты следует маркировать как отдельный протокол. Официальный checkpoint можно запустить один раз как внешний sanity check.

Архитектуры

Budget rule

Основная таблица: не более 2M trainable parameters на голову. Если H4 не помещается — уменьшите hidden width, а не расширяйте бюджет только ему.

Shared forward

За один frozen encoder forward получите features и передайте всем головам. Loss суммируется; оптимизаторы независимы. Это сокращает encoder compute примерно в число голов.

Не кэшируйте четыре слоя без расчётаДля CLIP L/14@336 один last-layer tensor — примерно 577×1024 значений на image. В fp16 это около 1.18 MB/image; четыре слоя для 31k train images — порядка 146 GB до metadata. Предпочтителен online shared-forward; cache только pooled features и, при необходимости, последний слой.

Единый train protocol

Что нельзя менять между головами

Иначе comparison превращается в набор отдельных моделей, где непонятно, что именно дало выигрыш.

Data и target

  • Все scores перевести в [0,1], higher = better.
  • Сначала reproducible concat sampler как у Q-Align mixed training.
  • Dataset-balanced sampler — отдельная ablation только для H0 и лучшей головы.
  • Split synthetic datasets по reference/content ID.

Optimization

  • SmoothL1 + λ·pairwise ranking, один λ для всех.
  • AMP, gradient clipping, early stop только по mixed validation macro-SRCC.
  • Seeds 8, 19, 25.
  • Backbone всегда eval(), gradients отключены.
Запрещённая утечкаНе используйте OOD test для выбора epoch, head width, layer indices или loss. Даже однократный «посмотрели и поправили» превращает held-out в validation.

Pareto

Оси зафиксировать до запуска

«Pareto-optimal» имеет смысл только с заранее определёнными осями и процедурой измерения.

ОсьОпределениеПравило
Quality ↑Macro mean SRCC на CLIVE, CSIQ, TID2013, AGIQA-3KКаждая база имеет одинаковый вес.
Robustness ↑Worst-dataset SRCCTie-break между близкими macro mean.
Latency ↓End-to-end batch-1, включая frozen encoderОдна GPU; 100 warmup + 500 repeats; p50 и p95.
Head cost ↓Trainable params и head-only FLOPsОтдельно от total encoder FLOPs.
Memory ↓Peak inference VRAMОдинаковая precision и input size.
Заранее заданный успехСложная агрегация оправдана, если улучшает macro OOD-SRCC не меньше чем на +0.01 к H1, выигрывает минимум на 3 из 4 held-out баз и остаётся ≤2M trainable params. Иначе практический победитель — H1, и это ценный отрицательный результат.

План на 10 дней

Сначала один encoder, потом перенос

Полная сетка запускается каскадом: слабые головы на E1 не получают автоматически дорогой E2 sweep.

День 1

Data audit

Manifest, score direction, split policy, 30 визуальных samples на базу.

День 2

Linear + H0

Overfit-64 и полный KADID smoke-run на CLIP.

День 3

H1

Перенести gated MLP из WACV-style baseline; проверить число параметров.

Дни 4–5

H2–H4

Query pooling, patch weighting, multi-layer fusion; unit tests на shapes/masks.

День 6

CLIP tournament

Один seed на всех головах; оставить H1 + две лучшие сложные.

Дни 7–8

SigLIP 2 transfer

Те же головы, budget и loss. Изменяется только adapter размерности входа.

День 9

3 seeds + OOD

Финальные H1 + топ-2 головы; все четыре held-out базы.

День 10

Pareto + freeze

Latency/VRAM, bootstrap CI, вывод о переносе между encoders, reproduction command.
