Установите PyTorch по официальному селектору, затем зависимости ниже. Зафиксируйте версии в первом коммите.

Соберите единый manifest

Одна строка на изображение: path, score_raw, score_01, reference_id, distortion_id, severity. Split делается по reference_id, не по файлам.

Основной d(x)

Frozen ARNIQA representation: извлеките глобальный feature до финального quality regressor, L2-нормализуйте и спроецируйте в размерность queries. Не обучайте ARNIQA на школьных split.

Код и веса ARNIQA

Диагностики prior

Oracle text prior из канонического имени искажения — верхняя граница, не NR-IQA результат. CLIP-IQA attributes — optional: это quality/attribute logits, а не чистый тип искажения.

CLIP-IQA

Интервенции: проверяем, что prior действительно используется

Matched

Правильный d(x). Основной результат.

Shuffled

d случайно переставлен внутри batch. Качество должно падать.

Zeroed

d=0. Отделяет полезность prior от лишних параметров.

Дополнительно: oracle d и deliberately wrong family. Attention-weight на prefix-токене сам по себе не считается объяснением.

Протокол LODO

Разделите два уровня переноса

ARNIQA видел синтетические искажения при pretraining. Поэтому отдельно оцениваются перенос обучаемой IQA-головы и перенос всей системы.

Head-LODO

Практичный core

Frozen ARNIQA разрешён. Из train IQA-head удаляется одно заранее зафиксированное семейство KADID. Это тест: умеет ли механизм conditioning переносить prior на новый тип для головы.

Strict system-LODO

Только как дополнительный тест

Ни один обучаемый или pre-trained модуль не должен был видеть held-out искажение. Для ARNIQA это обычно нельзя гарантировать; не называйте Head-LODO строгим system-LODO.

Зафиксируйте до запускаИспользуйте семь групп с официальной страницы KADID: blur 01–03, color 04–08, compression 09–10, noise 11–15, brightness 16–18, spatial 19–23, sharpness/contrast 24–25. Для каждого LODO-fold train/val/test остаются reference-disjoint; seeds 8, 19, 25. После первого результата mapping не менять.

Заранее заданный успехConditioning считается полезным, если лучший вариант даёт не меньше +0.01 macro OOD-SRCC к V0, CI разности не пересекает 0, а shuffled prior заметно ухудшает результат. Если нет — хороший вывод звучит: «при данном backbone и prior механизм инъекции не важен / prior не используется».

План на 10 дней

Критический путь

Каждый день заканчивается артефактом в репозитории, а не только устным статусом.

День 1

Data contract

Manifest, score direction, reference-disjoint split, 30 ручных визуальных проверок.

День 2

Sanity baseline

Frozen CLIP pooled feature → MLP и переобучение на 64 samples.

Дни 3–4

Query baseline + prior

V0 cross-attention, затем deterministic ARNIQA extractor и cache ключей/версий.

Дни 5–6

V1–V3

Additive, FiLM, prefix/KV; один unit test на identity-init для FiLM.

День 7

Interventions

Matched, shuffled, zeroed; анализ 20 лучших/худших delta.

Дни 8–9

3 seeds + external

Head-LODO и CSIQ/TID2013; LIVE — если доступ уже получен.

День 10

Freeze

Таблица, CI, latency, 4–6 страниц, checkpoint и reproduction command.
